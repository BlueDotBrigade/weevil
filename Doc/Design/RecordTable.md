# Record Table

How Weevil keeps a log's records in memory, and creates a record only when it is read (#1021). The plan is step 3 of [988-IndexingService.md](../Plans/988-IndexingService.md), and the design it followed is in [RecordsOnDemand](../Research/Weevil3/RecordsOnDemand/README.md).

## The Table

The parser fills a `RecordTable` (`BlueDotBrigade.Weevil.Data`, Core). It keeps each record as a row of columns, 21 bytes per record:

| Column | Type | Bytes |
|---|---|---|
| Line number | `int` | 4 |
| Content's offset in its chunk | `int` | 4 |
| Content's length | `int` | 4 |
| Facts: severity, multi-line, generated by the UI, keeps a string | `byte` | 1 |
| Timestamp | `DateTime` | 8 |

- **Blocks:** the columns are kept in blocks of 65,536 rows, so no array grows large.
- **Content:** the log's bytes are kept in chunks of about 16 MB (`ContentChunk`). A chunk directory says which record each chunk starts at. In disk mode a chunk holds no bytes and reads them back from the log ([DiskMode.md](DiskMode.md)).
- **Strings:** a record keeps its content as a string instead when it is UTF-16 in the other byte order or UTF-32 in RAM mode, or text a plugin changed. Its facts byte says so.
- **Immutable:** a table never changes once built.

## Records on Demand

- **Record lists:** callers read records through `RecordList` (Common), a read-only `IList<IRecord>`. Over a table, a `TableRecordList` holds the table, and the record numbers it lists unless it lists every record in order: 4 bytes per record.
- **A record is created each time a position is read,** and is not kept. Read a position once, rather than reading the same position many times.
- **Equality:** two records are equal when their line numbers are equal (#1135). Compare records with `Equals`, never by reference.
- **Without a record:** code that needs only part of a row reads it from the list, and creates no record:
  - `GetLineNumber(position)`;
  - `GetCreatedAt(position)`;
  - `GetFacts(position)`: severity, multi-line and generated by the UI;
  - `ReadContent(position, buffer)`: the text, decoded into a reused `ContentBuffer`.

  Find, the time-gap analyzers, the insights and elapsed times read rows this way (#1137, #1150). A filter still creates one record per row, because `IFilterStrategy.CanKeep` takes a record.
- **Filter results and the selection** are record lists over the view's table.
- **Clear** builds a new table of only the records it keeps. The records it clears, and the chunks only they were read from, are freed before Clear returns (#1022). Only whole chunks are freed.

## Memory

- **Working set per GB of log,** on the 4 GB log of the memory harness: 1.22 GB, against 3.0 GB for Weevil 2.12.1. #1086 asks for at most 1.2.
- **Managed memory per record,** on the reference log of the performance tests: 153 bytes in RAM, and 22 in disk mode.

The memory harness's [results](../Research/Weevil3/MemoryHarness/README.md#results) give each step's figures.
